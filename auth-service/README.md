# Служба авторизации (auth-service)

Учёт пользователей, вход, выдача и отзыв токенов, роли. Порт 8100, наружу не публикуется: все запросы идут через шлюз по пути `/api/auth/**`. Данные хранятся в схеме `auth`; схема создаётся и меняется только через Flyway (`src/main/resources/db/migration`).

## Токены

| | Токен доступа | Обновляемый токен |
| --- | --- | --- |
| Где у клиента | тело ответа, затем заголовок `Authorization: Bearer …` | куки `mediagrid_refresh` (HttpOnly, Secure, SameSite=Strict, путь `/api/auth`) |
| Срок | 15 минут | 30 дней |
| Проверка | любая служба сама, по открытому ключу с `/api/auth/jwks` | только служба авторизации, по отпечатку в базе |
| Отзыв | выход (токены этого входа), смена или сброс пароля, отключение, смена роли (все токены пользователя); шлюз перестаёт их принимать за 5 секунд | выход, смена или сброс пароля, отключение пользователя |

Токен доступа подписан ключом RSA (RS256). В нём: `sub` — идентификатор пользователя, `email`, `roles` — список ролей, `iss` — `mediagrid-auth`, `sid` — номер входа (общий для всех токенов, полученных обновлением после одного входа), `ver` — поколение токенов пользователя.

### Отзыв токенов доступа

Токен доступа проверяется по подписи, без обращения к службе авторизации, поэтому отозванные токены перечисляются явно в таблице `auth.access_revocations` — пока они не истекут сами (срок токена плюс минута на расхождение часов), потом записи удаляются.

- Выход и повторное предъявление заменённого обновляемого токена отзывают токены одного входа (по `sid`). Остальные входы пользователя — например, на другом устройстве — продолжают работать.
- Смена или сброс пароля, отключение и смена роли переводят пользователя на следующее поколение токенов (`auth.users.token_version`): все токены с меньшим `ver` отозваны. При смене роли вход сохраняется: веб-интерфейс получает 401, обновляет токен и получает токен с новой ролью.
- Шлюз раз в 5 секунд (`mediagrid.gateway.revocations.poll-interval` в `config/gateway.yml`) забирает список `GET /internal/auth/revocations` токеном службы (имя `gateway`, секрет `GATEWAY_CLIENT_SECRET`) и отвечает 401 на отозванный токен. Служба авторизации сверяет токены со своей базой сразу.
- Остальные службы отзыв не проверяют: снаружи до них можно дойти только через шлюз.
- Если служба авторизации недоступна, шлюз работает с последним полученным списком. Если шлюз запущен, а список ещё не получен ни разу, отозванные раньше токены проходят до своего истечения (не дольше 15 минут); вход в систему при этом не останавливается.

Обновляемый токен при каждом обновлении заменяется новым. Если предъявить уже заменённый токен, служба считает его перехваченным и отзывает всю цепочку этого входа. Поэтому веб-интерфейс не должен отправлять несколько запросов обновления одновременно.

Ключ подписи создаётся при первом запуске и хранится в таблице `auth.signing_keys`: выданные токены переживают перезапуск службы. Эту таблицу нужно беречь так же, как пароли: с закрытым ключом можно выпустить любой токен.

## Роли

- `ADMIN` — управление учётными записями и весь контент.
- `USER` — работа со своими файлами.

Открытой регистрации нет: учётные записи заводит администратор. Первый администратор создаётся при запуске из переменных `ADMIN_EMAIL` и `ADMIN_PASSWORD`, если администраторов в базе ещё нет; дальше эти переменные ни на что не влияют. Последнего действующего администратора нельзя отключить или понизить.

### Восстановление пароля администратора

Если администратор забыл пароль, а другого администратора нет, пароль задаётся на сервере:

```
docker compose exec auth-service reset-admin-password admin@example.com
```

- Команда дважды спрашивает новый пароль (8–64 символа) и не показывает его на экране. Без терминала она читает одну строку со стандартного ввода, например `docker compose exec -T auth-service reset-admin-password <почта> < файл`.
- Учётная запись включается, все её сеансы завершаются, выданные токены доступа отзываются.
- Работает только для администраторов: пароли пользователей сбрасывает администратор в интерфейсе. При ошибке в почте выводится список администраторов.
- Это отдельная небольшая программа из архива службы (`AdminPasswordReset`): служба при этом не перезапускается, в базу программа ходит учётной записью службы. Кто может выполнить команду, тот имеет доступ к серверу — других проверок нет.

Службы, которым нужно обращаться к другим службам, получают токен с ролью `SERVICE` (сейчас это служба обработки и шлюз). У такого токена вместо номера пользователя в `sub` стоит имя службы. Он открывает только внутренние пути `/internal/**`, которые шлюз наружу не пропускает; пути пользователей `/api/**` для него закрыты.

## Программный интерфейс

Все ошибки возвращаются в едином формате: `{"code", "message", "traceId", "timestamp"}`.

### Вход и сеанс

| Запрос | Доступ | Описание |
| --- | --- | --- |
| `POST /api/auth/login` `{email, password}` | все | вход; ответ `{accessToken, tokenType, expiresIn, user}` и куки с обновляемым токеном |
| `POST /api/auth/refresh` | по куки | новая пара токенов, ответ как у входа |
| `POST /api/auth/logout` | все | завершение входа, куки стирается; 204 |
| `GET /api/auth/me` | вошедший | своя учётная запись |
| `PUT /api/auth/me/password` `{currentPassword, newPassword}` | вошедший | смена пароля, все входы завершаются; 204 |
| `GET /api/auth/jwks` | все | открытые ключи для проверки токенов доступа |

### Токены служб (только внутри сети, шлюз не пропускает)

| Запрос | Описание |
| --- | --- |
| `POST /internal/auth/token`, заголовок `Authorization: Basic base64(имя:секрет)` | токен службы с ролью `SERVICE` на 15 минут; ответ `{accessToken, tokenType, expiresIn}`. Службы и секреты — `mediagrid.auth.service-clients` в `config/auth-service.yml` (секрет не короче 32 символов, пустой — вход закрыт): `processing-service`, `gateway` |
| `GET /internal/auth/revocations`, токен службы | действующие отзывы токенов доступа: `{revocations: [{userId, sessionId, minVersion, expiresAt}]}`; задано либо `sessionId` (отозван вход), либо `minVersion` (отозваны поколения меньше). В трассы эти запросы не пишутся |

### Управление пользователями (только ADMIN)

| Запрос | Описание |
| --- | --- |
| `GET /api/auth/admin/users?page=0&size=20` | список, ответ `{items, page, size, total}` |
| `POST /api/auth/admin/users` `{email, password, displayName, role}` | создание; 201 |
| `GET /api/auth/admin/users/{id}` | одна учётная запись |
| `PATCH /api/auth/admin/users/{id}` `{displayName?, role?, enabled?}` | изменение; отключение завершает все входы пользователя |
| `PUT /api/auth/admin/users/{id}/password` `{newPassword}` | сброс пароля, все входы завершаются; 204 |

Пароль — от 8 до 64 символов. Почта хранится в нижнем регистре.

### Коды ошибок

| Код | Статус | Когда |
| --- | --- | --- |
| `INVALID_CREDENTIALS` | 401 | неверная почта или пароль (одинаково для обоих случаев) |
| `ACCOUNT_DISABLED` | 403 | учётная запись отключена |
| `INVALID_REFRESH_TOKEN` | 401 | обновляемый токен отсутствует, истёк, отозван |
| `INVALID_CLIENT` | 401 | неверное имя службы или секрет |
| `UNAUTHORIZED` | 401 | нет действующего токена доступа |
| `FORBIDDEN` | 403 | недостаточно прав |
| `VALIDATION_ERROR` | 400 | некорректные поля запроса |
| `INVALID_CURRENT_PASSWORD` | 400 | при смене пароля неверно указан текущий |
| `EMAIL_TAKEN` | 409 | почта уже занята |
| `LAST_ADMIN` | 409 | попытка отключить или понизить последнего администратора |
| `NOT_FOUND` | 404 | пользователь не найден |
