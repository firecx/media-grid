# Служба авторизации (auth-service)

Учёт пользователей, вход, выдача и отзыв токенов, роли. Порт 8100, наружу не публикуется: все запросы идут через шлюз по пути `/api/auth/**`. Данные хранятся в схеме `auth`; схема создаётся и меняется только через Flyway (`src/main/resources/db/migration`).

## Токены

| | Токен доступа | Обновляемый токен |
| --- | --- | --- |
| Где у клиента | тело ответа, затем заголовок `Authorization: Bearer …` | куки `mediagrid_refresh` (HttpOnly, Secure, SameSite=Strict, путь `/api/auth`) |
| Срок | 15 минут | 30 дней |
| Проверка | любая служба сама, по открытому ключу с `/api/auth/jwks` | только служба авторизации, по отпечатку в базе |
| Отзыв | нельзя, истекает сам | выход, смена или сброс пароля, отключение пользователя |

Токен доступа подписан ключом RSA (RS256). В нём: `sub` — идентификатор пользователя, `email`, `roles` — список ролей, `iss` — `mediagrid-auth`.

Обновляемый токен при каждом обновлении заменяется новым. Если предъявить уже заменённый токен, служба считает его перехваченным и отзывает всю цепочку этого входа. Поэтому веб-интерфейс не должен отправлять несколько запросов обновления одновременно.

Ключ подписи создаётся при первом запуске и хранится в таблице `auth.signing_keys`: выданные токены переживают перезапуск службы. Эту таблицу нужно беречь так же, как пароли: с закрытым ключом можно выпустить любой токен.

## Роли

- `ADMIN` — управление учётными записями и весь контент.
- `USER` — работа со своими файлами.

Открытой регистрации нет: учётные записи заводит администратор. Первый администратор создаётся при запуске из переменных `ADMIN_EMAIL` и `ADMIN_PASSWORD`, если администраторов в базе ещё нет; дальше эти переменные ни на что не влияют. Последнего действующего администратора нельзя отключить или понизить.

Службы, которым нужно обращаться к другим службам, получают токен с ролью `SERVICE` (сейчас это только служба обработки). У такого токена вместо номера пользователя в `sub` стоит имя службы. Он открывает только внутренние пути `/internal/**`, которые шлюз наружу не пропускает; пути пользователей `/api/**` для него закрыты.

## Программный интерфейс

Все ошибки возвращаются в едином формате: `{"code", "message", "traceId", "timestamp"}`.

### Вход и сеанс

| Запрос | Доступ | Описание |
| --- | --- | --- |
| `POST /api/auth/login` `{email, password}` | все | вход; ответ `{accessToken, tokenType, expiresIn, user}` и куки с обновляемым токеном |
| `POST /api/auth/refresh` | по куки | новая пара токенов, ответ как у входа |
| `POST /api/auth/logout` | все | завершение входа, куки стирается; 204 |
| `GET /api/auth/me` | вошедший | своя учётная запись |
| `PUT /api/auth/me/password` `{currentPassword, newPassword}` | вошедший | смена пароля, все входы завершаются; 204 |
| `GET /api/auth/jwks` | все | открытые ключи для проверки токенов доступа |

### Токены служб (только внутри сети, шлюз не пропускает)

| Запрос | Описание |
| --- | --- |
| `POST /internal/auth/token`, заголовок `Authorization: Basic base64(имя:секрет)` | токен службы с ролью `SERVICE` на 15 минут; ответ `{accessToken, tokenType, expiresIn}`. Службы и секреты — `mediagrid.auth.service-clients` в `config/auth-service.yml` (секрет не короче 32 символов, пустой — вход закрыт) |

### Управление пользователями (только ADMIN)

| Запрос | Описание |
| --- | --- |
| `GET /api/auth/admin/users?page=0&size=20` | список, ответ `{items, page, size, total}` |
| `POST /api/auth/admin/users` `{email, password, displayName, role}` | создание; 201 |
| `GET /api/auth/admin/users/{id}` | одна учётная запись |
| `PATCH /api/auth/admin/users/{id}` `{displayName?, role?, enabled?}` | изменение; отключение завершает все входы пользователя |
| `PUT /api/auth/admin/users/{id}/password` `{newPassword}` | сброс пароля, все входы завершаются; 204 |

Пароль — от 8 до 64 символов. Почта хранится в нижнем регистре.

### Коды ошибок

| Код | Статус | Когда |
| --- | --- | --- |
| `INVALID_CREDENTIALS` | 401 | неверная почта или пароль (одинаково для обоих случаев) |
| `ACCOUNT_DISABLED` | 403 | учётная запись отключена |
| `INVALID_REFRESH_TOKEN` | 401 | обновляемый токен отсутствует, истёк, отозван |
| `INVALID_CLIENT` | 401 | неверное имя службы или секрет |
| `UNAUTHORIZED` | 401 | нет действующего токена доступа |
| `FORBIDDEN` | 403 | недостаточно прав |
| `VALIDATION_ERROR` | 400 | некорректные поля запроса |
| `INVALID_CURRENT_PASSWORD` | 400 | при смене пароля неверно указан текущий |
| `EMAIL_TAKEN` | 409 | почта уже занята |
| `LAST_ADMIN` | 409 | попытка отключить или понизить последнего администратора |
| `NOT_FOUND` | 404 | пользователь не найден |
