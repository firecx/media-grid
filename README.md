# MediaGrid

Автоматизированная медиасистема для хранения, каталогизации и предоставления доступа к медиафайлам.
Микросервисная архитектура, один репозиторий (монорепозиторий).

## Стек

| Компонент | Версия |
| --- | --- |
| Java | 21 |
| Maven | 3.10.0 |
| Spring Boot | 4.1.x |
| Spring Cloud | 2025.1.x |
| PostgreSQL (образ) | `postgres:18.6-alpine3.24` |
| Шина сообщений | RabbitMQ 4 |
| Веб-интерфейс | Node.js 26 (только сборка), React 19, TypeScript 6, Vite 8, Mantine 9 |
| Точка входа | nginx 1.30 |

## Структура

- `discovery/` — регистр служб (Eureka), порт 8761
- `config-server/` — центр конфигурации, порт 8888
- `auth-service/` — служба авторизации, порт 8100 (только через шлюз). Описание — в [auth-service/README.md](auth-service/README.md)
- `media-service/` — служба медиаданных, порт 8200 (только через шлюз). Описание — в [media-service/README.md](media-service/README.md)
- `storage-service/` — служба загрузки и хранения файлов, порт 8300 (только через шлюз). Описание — в [storage-service/README.md](storage-service/README.md)
- `processing-service/` — служба обработки (миниатюры, превью, перекодирование через ffmpeg; очередь задач), порт 8400 (только через шлюз). Описание — в [processing-service/README.md](processing-service/README.md)
- `web/` — веб-интерфейс и nginx, единственная точка входа для браузера (порт `MEDIAGRID_HTTP_PORT`, по умолчанию 8080): отдаёт интерфейс, `/api` передаёт шлюзу. Описание — в [web/README.md](web/README.md)
- `gateway/` — шлюз, порт 8080 внутри сети (наружу не публикуется). Запросы `/api/<раздел>/**` передаются службам: `auth` — авторизации, `media` — медиаданных, `files` — загрузки и хранения, `processing` — обработки. Маршруты — в `config/gateway.yml`. Шлюз проверяет токен доступа до передачи запроса: без токена доступны только вход, обновление, выход и выдача файла по подписанной ссылке; пути `/api/<раздел>/admin/**` — только администратору
- `config/` — настройки служб, которые раздаёт центр конфигурации: `application.yml` — общие для всех, `<имя службы>.yml` — для отдельной службы. Пароли здесь не хранятся, только подстановки вида `${POSTGRES_PASSWORD}`
- `common/` — общие контракты (события очереди, формат ошибок), без бизнес-логики
- `service-support/` — общий код прикладных служб (обработка ошибок, проверка токенов, настройка защиты, шина сообщений); подключается автоматически
- `infra/` — служебные файлы инфраструктуры (схемы базы данных и т. п.)
- `docker-compose.yaml` — запуск всей системы
- служебные модули и службы добавляются в корень репозитория по одному каталогу на службу

У каждой службы свой `pom.xml`; родительский `pom.xml` в корне хранит только версии и список модулей.

## Запуск окружения

```
cp .env.example .env     # замените пароли и секреты (STORAGE_LINK_SECRET, PROCESSING_CLIENT_SECRET)
docker compose up -d
```

Интерфейс — http://localhost:8080, вход — `ADMIN_EMAIL` и `ADMIN_PASSWORD` из `.env`.

## Среда разработки

- Java 21 и Maven 3.10 — для служб (`mvn verify`).
- Node.js 26 — только для разработки интерфейса (`web/`); в Docker интерфейс собирается сам. Ставится через fnm, который берёт версию из `web/.node-version`:

  ```
  scoop install fnm
  # в профиль PowerShell ($PROFILE):
  fnm env --use-on-cd --shell powershell | Out-String | Invoke-Expression
  fnm install 26
  ```

## Версии проекта

Формат `1.2.3` (ГЛОБАЛЬНАЯ.КРУПНАЯ.МЕЛКАЯ):

1. **Первое число** — глобальные релизы, законченное программное обеспечение.
2. **Второе число** — крупное обновление, не меняющее суть системы; возможно добавление службы (юнита).
3. **Третье число** — маленькие обновления, исправления ошибок и прочие правки.

До первого законченного релиза версия начинается с нуля: `0.2.0`, `0.3.0` и т. д.
Текущая версия: `0.8.0-SNAPSHOT` (задаётся в родительском `pom.xml`, у модулей наследуется).
Смена версии во всех модулях одной командой:

```
mvn versions:set -DnewVersion=0.6.0 -DgenerateBackupPoms=false
```

Версия образа каждой службы совпадает с версией проекта.

Суффикс `-SNAPSHOT` означает версию в работе: например, `0.4.0-SNAPSHOT` — это будущая `0.4.0`, её сборки
перезаписывают друг друга. Версия без суффикса — выпуск, его содержимое больше не меняется (исправления
выходят следующей версией). Порядок выпуска:

1. работа ведётся под `X.Y.0-SNAPSHOT`, изменения записываются в `CHANGELOG.md` в раздел «в работе»;
2. при выпуске суффикс убирается (`mvn versions:set -DnewVersion=X.Y.0 ...`), раздел в `CHANGELOG.md` получает дату;
3. после коммита ставится метка `vX.Y.0`, и версия сразу переводится на следующую `-SNAPSHOT`.

Что вошло в каждую версию — в [CHANGELOG.md](CHANGELOG.md).
