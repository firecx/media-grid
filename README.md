# MediaGrid

Автоматизированная медиасистема для хранения, каталогизации и предоставления доступа к медиафайлам.
Микросервисная архитектура, один репозиторий (монорепозиторий).

## Стек

| Компонент | Версия |
| --- | --- |
| Java | 21 |
| Maven | 3.10.0 |
| Spring Boot | 4.1.x |
| Spring Cloud | 2025.1.x |
| PostgreSQL (образ) | `postgres:18.6-alpine3.24` |
| Шина сообщений | RabbitMQ 4 |

## Структура

- `discovery/` — регистр служб (Eureka), порт 8761
- `common/` — общие контракты (события очереди, формат ошибок), без бизнес-логики
- `infra/` — служебные файлы инфраструктуры (схемы базы данных и т. п.)
- `docker-compose.yaml` — запуск всей системы
- служебные модули и службы добавляются в корень репозитория по одному каталогу на службу

У каждой службы свой `pom.xml`; родительский `pom.xml` в корне хранит только версии и список модулей.

## Запуск окружения

```
cp .env.example .env     # замените пароли
docker compose up -d
```

## Версии проекта

Формат `1.2.3` (ГЛОБАЛЬНАЯ.КРУПНАЯ.МЕЛКАЯ):

1. **Первое число** — глобальные релизы, законченное программное обеспечение.
2. **Второе число** — крупное обновление, не меняющее суть системы; возможно добавление службы (юнита).
3. **Третье число** — маленькие обновления, исправления ошибок и прочие правки.

До первого законченного релиза версия начинается с нуля: `0.2.0`, `0.3.0` и т. д.
Текущая версия: `0.1.0-SNAPSHOT` (задаётся в родительском `pom.xml`, у модулей наследуется).
Смена версии во всех модулях одной командой:

```
mvn versions:set -DnewVersion=0.2.0 -DgenerateBackupPoms=false
```

Версия образа каждой службы совпадает с версией проекта.
