# История версий

Порядок нумерации описан в [README.md](README.md#версии-проекта). Новые версии добавляются сверху.

## 0.5.0 — 2026-10-03

Служба медиаданных.

### Добавлено
- Служба `media-service` (порт 8200, только через шлюз): каталог файлов, категории и теги, поиск с фильтрами и сортировкой, права владельца и видимость `PRIVATE`/`PUBLIC`. Описание программного интерфейса — `media-service/README.md`.
- Порядок загрузки: сначала запись в каталоге (`PENDING_UPLOAD`), затем файл в службу хранения; статус меняется по событиям `file.uploaded` и `processing.completed`. Записи без загруженного файла удаляются через 24 часа.
- Шина сообщений: общая точка обмена `mediagrid.events`, ключи событий и событие `MediaDeletedEvent` в `common`; у каждой очереди есть очередь `.dlq` для сообщений, которые не удалось обработать после трёх попыток.
- Общие настройки RabbitMQ в `config/application.yml`.
- Автотесты службы на настоящих PostgreSQL и RabbitMQ в контейнерах.

### Изменено
- Окончания строк закреплены как LF во всех файлах, в том числе в рабочей папке под Windows (`.gitattributes`); двоичные файлы не преобразуются.
- Подключение к базе службы авторизации и медиаданных работает в схеме службы (`hikari.schema`), в том числе для запросов на чистом SQL.

### Исправлено
- Если токен нельзя проверить из-за недоступности службы авторизации, шлюз и служба медиаданных отвечают 503 `SERVICE_UNAVAILABLE`, а не 500.

## 0.4.0 — 2026-10-02

Служба авторизации.

### Добавлено
- Служба `auth-service` (порт 8100, только через шлюз): вход, обновление и выход, своя учётная запись и смена пароля; управление пользователями для администратора по отдельному пути `/api/auth/admin/**`. Описание программного интерфейса — `auth-service/README.md`.
- Токены доступа (15 минут, подпись RS256, открытые ключи на `/api/auth/jwks`) и обновляемые токены (30 дней, куки HttpOnly; при каждом обновлении заменяются, повторное предъявление заменённого отзывает всю цепочку входа).
- Роли ADMIN и USER. Открытой регистрации нет; первый администратор создаётся из `ADMIN_EMAIL` и `ADMIN_PASSWORD`.
- Схема `auth` с изменениями через Flyway; ошибки в едином формате `ApiError`.
- Автотесты службы на настоящем PostgreSQL в контейнере (Testcontainers).
- Проверка токенов доступа в шлюзе: без токена пропускаются только вход, обновление, выход и открытые ключи; пути `/api/<раздел>/admin/**` требуют роли ADMIN; всё вне `/api/**` закрыто. Открытые ключи шлюз получает у службы авторизации через регистр служб и балансировщик.
- Ошибки шлюза (нет входа, нет прав, не найдено, служба недоступна) — в едином формате `ApiError`.
- Общие параметры проверки токенов (`mediagrid.security`) в `config/application.yml` для всех служб.
- Автотесты шлюза: проверка подписи, срока, издателя и ролей.

## 0.3.0 — 2026-10-02

Шлюз.

### Добавлено
- Служба `gateway` (порт 8080): единая точка входа, передаёт запросы `/api/auth/**`, `/api/media/**`, `/api/files/**` службам авторизации, медиаданных, загрузки и хранения. Службы находит через регистр служб, настройки и маршруты получает из центра конфигурации (`config/gateway.yml`). Тело запроса передаётся потоком, без буферизации в памяти.
- Служебные точки шлюза вынесены на порт 8081, который наружу не публикуется; список маршрутов доступен там только для чтения.

## 0.2.0 — 2026-10-02

Центр конфигурации.

### Добавлено
- Служба `config-server` (порт 8888): раздаёт настройки служб из каталога `config/`, читая их с диска. Регистрируется в регистре служб.
- Каталог `config/` с общими настройками служб (`application.yml`): адрес регистра служб, открытые точки проверки состояния. Пароли в нём не хранятся, только подстановки из переменных среды.
- Служба `config-server` в `docker-compose.yaml`; каталог `config/` подключается к ней томом.
- Файл истории версий (этот файл).

### Изменено
- Образы служб собираются из всего репозитория (лишнее отсекает `.dockerignore`), зависимости Maven сохраняются между сборками. Добавление новых модулей больше не ломает сборку образов уже существующих служб.
- В `discovery` и `config-server` отключён кэш балансировщика нагрузки: эти службы никого не вызывают, и предупреждение при запуске больше не выводится.

## 0.1.0 — 2026-10-02

Каркас проекта и регистр служб. Версия собиралась как `0.1.0-SNAPSHOT`, отдельным выпуском не отмечалась.

### Добавлено
- Родительский `pom.xml` (Java 21, Spring Boot 4.1.1, Spring Cloud 2025.1.2) и общий модуль `common`: события очереди `FileUploadedEvent`, `ProcessingCompletedEvent` и единый формат ошибки `ApiError`.
- `docker-compose.yaml` с PostgreSQL 18 и RabbitMQ 4, сценарий создания схем базы данных по службам (`infra/postgres/init.sql`), `.env.example`.
- Служба `discovery` (регистр служб на Eureka, порт 8761) с проверкой готовности в `docker-compose.yaml`.
- Правила нумерации версий; версия образа службы совпадает с версией проекта (`MEDIAGRID_VERSION`).
