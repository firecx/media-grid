# История версий

Порядок нумерации описан в [README.md](README.md#версии-проекта). Новые версии добавляются сверху.

## 0.8.0 — в работе

Веб-интерфейс.

### Добавлено
- Веб-интерфейс `web/` (React 19, TypeScript 6, Vite 8, Mantine 9, TanStack Query, React Router 8). Описание — `web/README.md`.
  - Вход с восстановлением сеанса по куки и общим обновлением токена при 401.
  - Каталог: поиск, фильтры, теги, сортировка, страницы, миниатюры.
  - Загрузка нескольких файлов частями с ходом загрузки, продолжением после обрыва и отменой; затем ход обработки.
  - Страница файла: просмотр изображений, видео с перемоткой и звука, сведения и метаданные обработки, изменение, удаление, скачивание.
  - Администрирование: пользователи, категории, очередь обработки с повтором.
  - Смена пароля, светлая и тёмная темы, раскладка для телефона.
- Библиотека компонентов Mantine подключается только в `web/src/ui`: страницы используют собственные компоненты и переменные оформления, прямой импорт Mantine вне `src/ui` запрещён правилом ESLint. Так можно перейти на свои стили, не переписывая страницы.
- Контейнер `web` (nginx): единственная точка входа для браузера (порт `MEDIAGRID_HTTP_PORT`, по умолчанию 8080). Отдаёт интерфейс и передаёт `/api` шлюзу без буферизации (большие загрузки, потоковая выдача), ограничивает частоту попыток входа (10 в минуту), выставляет заголовки безопасности.
- Node.js 26 для сборки интерфейса: `.node-version`, поле `engines`, образ сборки `node:26-alpine`; сборка Maven от Node не зависит.

- Оформление интерфейса: светлая и тёмная темы. В тёмной тёмная вся страница, текст и значки контрастные (все пары цветов не ниже WCAG AA). Цвета выделения меняются вместе с темой: в светлой — синий, тёмно-синий, фиолетовый; в тёмной — бирюзовый, аквамарин, голубо-зелёный. Тема выставляется до загрузки приложения, без белой вспышки.

### Изменено
- Шлюз больше не публикуется наружу: запросы приходят через `web`.

## 0.7.0 — 2026-10-03

Служба обработки.

### Добавлено
- Служба `processing-service` (порт 8400, только через шлюз; ffmpeg в образе). Описание — `processing-service/README.md`.
  - Очередь задач в базе (схема `processing`): событие `file.uploaded` ставит задачу, исполнители берут её через `FOR UPDATE SKIP LOCKED`. Долгое перекодирование не упирается в ограничение RabbitMQ на время подтверждения, а задачи переживают перезапуск службы.
  - Миниатюра и превью в JPEG для изображений, видео (кадр) и звука (обложка).
  - Перекодирование только того, что браузер не воспроизведёт: видео — в MP4 (H.264 и AAC, подходящие дорожки копируются), звук — в M4A (AAC). Исходный файл не меняется.
  - Метаданные обработки: длительность, размер кадра, кодеки.
  - Ход обработки: `GET /api/processing/{id}` (этап и процент).
  - Администрирование очереди: `GET /api/processing/admin/jobs` и повтор `POST /api/processing/admin/jobs/{id}/retry`.
  - Устойчивость: временные сбои повторяются с нарастающей паузой; при недоступности службы хранения размыкается цепь, и новые задачи не берутся; брошенные задачи возвращаются в очередь; итог досылается, пока не уйдёт. Удаление записи останавливает ffmpeg.
- Токены служб: служба авторизации выдаёт токен с ролью `SERVICE` по имени и секрету службы (`POST /internal/auth/token`, `mediagrid.auth.service-clients`). Переменная `PROCESSING_CLIENT_SECRET`.
- Производные файлы в службе хранения (таблица `file_variants`):
  - внутренний интерфейс `/internal/files/**` для службы обработки (только токен службы);
  - ссылки на `thumbnail`, `preview` и `playback` (параметр `variant`); если версии для воспроизведения нет, ссылка ведёт на исходный файл;
  - производные удаляются вместе с файлом.
- Маршрут шлюза `/api/processing/**`, том `processing-work`.

### Изменено
- События: в `file.uploaded` вместо ключа хранилища передаётся владелец (`ownerId`); в `processing.completed` вместо ключа превью — признак `hasPreview`. Где лежат файлы, знает только служба хранения.
- Пути `/api/**` всех служб и шлюза открыты только ролям USER и ADMIN; токен службы на них не действует.
- В подпись ссылки на файл входит вид файла (`variant`), в адресе ссылки появился параметр `variant`.

### Исправлено
- Служба медиаданных: если `processing.completed` приходил раньше `file.uploaded`, запись навсегда оставалась в `UPLOADED`. Теперь итог обработки учитывается и в этом случае.
- Шлюз: недоступная служба, которая ещё числится в регистре, давала 500 через 30 секунд ожидания. Теперь шлюз отвечает 503 `SERVICE_UNAVAILABLE` через 2 секунды (тайм-аут соединения).
- Служба хранения: тело `POST /api/files/{id}/links` без поля `download` (например, `{}`) отклонялось с 400: в Jackson 3 отсутствующее поле примитивного типа — ошибка. Теперь все поля тела необязательны.

## 0.6.0 — 2026-10-03

Служба загрузки и хранения.

### Добавлено
- Служба `storage-service` (порт 8300, только через шлюз). Описание программного интерфейса — `storage-service/README.md`.
  - Загрузка файла под номером записи каталога: одним запросом или частями (`Content-Range`), с докачкой после обрыва (`HEAD` → `Upload-Offset`). После получения файла публикуется событие `file.uploaded`.
  - Выдача по подписанным ссылкам с ограниченным сроком действия (HMAC-SHA256, по умолчанию 4 часа), без токена, с частичной загрузкой (`Range`) для перемотки.
  - Удаление файла по событию `media.deleted`.
  - Схема `storage` (Flyway), хранилище — локальный каталог за интерфейсом `StorageProvider`, в Docker — том `storage-data`.
- Устойчивость к сбоям при обращении службы хранения к службе медиаданных: тайм-ауты, повторы с нарастающей паузой, размыкание цепи (Resilience4j).
- Общий модуль `service-support` для прикладных служб: единый обработчик ошибок `ApiException`, проверка токенов по открытым ключам службы авторизации (с ответом 503 при её недоступности), общая настройка защиты, `CurrentUser`, преобразователь сообщений шины и объявление очередей с `.dlq` (`EventQueues`). Подключается автоматически.
- Переменная среды `STORAGE_LINK_SECRET` — ключ подписи ссылок (`.env.example`).
- Автотесты службы хранения на настоящих PostgreSQL и RabbitMQ в контейнерах; отдельные тесты повторов и размыкания цепи.

### Изменено
- Шлюз пропускает без токена `GET` и `HEAD /api/files/*/content`: файл по ссылке проверяется подписью.
- Службы авторизации и медиаданных используют `service-support` вместо собственных копий обработчика ошибок, проверки токенов и настройки защиты.

## 0.5.0 — 2026-10-03

Служба медиаданных.

### Добавлено
- Служба `media-service` (порт 8200, только через шлюз): каталог файлов, категории и теги, поиск с фильтрами и сортировкой, права владельца и видимость `PRIVATE`/`PUBLIC`. Описание программного интерфейса — `media-service/README.md`.
- Порядок загрузки: сначала запись в каталоге (`PENDING_UPLOAD`), затем файл в службу хранения; статус меняется по событиям `file.uploaded` и `processing.completed`. Записи без загруженного файла удаляются через 24 часа.
- Шина сообщений: общая точка обмена `mediagrid.events`, ключи событий и событие `MediaDeletedEvent` в `common`; у каждой очереди есть очередь `.dlq` для сообщений, которые не удалось обработать после трёх попыток.
- Общие настройки RabbitMQ в `config/application.yml`.
- Автотесты службы на настоящих PostgreSQL и RabbitMQ в контейнерах.

### Изменено
- Окончания строк закреплены как LF во всех файлах, в том числе в рабочей папке под Windows (`.gitattributes`); двоичные файлы не преобразуются.
- Подключение к базе службы авторизации и медиаданных работает в схеме службы (`hikari.schema`), в том числе для запросов на чистом SQL.

### Исправлено
- Если токен нельзя проверить из-за недоступности службы авторизации, шлюз и служба медиаданных отвечают 503 `SERVICE_UNAVAILABLE`, а не 500.

## 0.4.0 — 2026-10-02

Служба авторизации.

### Добавлено
- Служба `auth-service` (порт 8100, только через шлюз): вход, обновление и выход, своя учётная запись и смена пароля; управление пользователями для администратора по отдельному пути `/api/auth/admin/**`. Описание программного интерфейса — `auth-service/README.md`.
- Токены доступа (15 минут, подпись RS256, открытые ключи на `/api/auth/jwks`) и обновляемые токены (30 дней, куки HttpOnly; при каждом обновлении заменяются, повторное предъявление заменённого отзывает всю цепочку входа).
- Роли ADMIN и USER. Открытой регистрации нет; первый администратор создаётся из `ADMIN_EMAIL` и `ADMIN_PASSWORD`.
- Схема `auth` с изменениями через Flyway; ошибки в едином формате `ApiError`.
- Автотесты службы на настоящем PostgreSQL в контейнере (Testcontainers).
- Проверка токенов доступа в шлюзе: без токена пропускаются только вход, обновление, выход и открытые ключи; пути `/api/<раздел>/admin/**` требуют роли ADMIN; всё вне `/api/**` закрыто. Открытые ключи шлюз получает у службы авторизации через регистр служб и балансировщик.
- Ошибки шлюза (нет входа, нет прав, не найдено, служба недоступна) — в едином формате `ApiError`.
- Общие параметры проверки токенов (`mediagrid.security`) в `config/application.yml` для всех служб.
- Автотесты шлюза: проверка подписи, срока, издателя и ролей.

## 0.3.0 — 2026-10-02

Шлюз.

### Добавлено
- Служба `gateway` (порт 8080): единая точка входа, передаёт запросы `/api/auth/**`, `/api/media/**`, `/api/files/**` службам авторизации, медиаданных, загрузки и хранения. Службы находит через регистр служб, настройки и маршруты получает из центра конфигурации (`config/gateway.yml`). Тело запроса передаётся потоком, без буферизации в памяти.
- Служебные точки шлюза вынесены на порт 8081, который наружу не публикуется; список маршрутов доступен там только для чтения.

## 0.2.0 — 2026-10-02

Центр конфигурации.

### Добавлено
- Служба `config-server` (порт 8888): раздаёт настройки служб из каталога `config/`, читая их с диска. Регистрируется в регистре служб.
- Каталог `config/` с общими настройками служб (`application.yml`): адрес регистра служб, открытые точки проверки состояния. Пароли в нём не хранятся, только подстановки из переменных среды.
- Служба `config-server` в `docker-compose.yaml`; каталог `config/` подключается к ней томом.
- Файл истории версий (этот файл).

### Изменено
- Образы служб собираются из всего репозитория (лишнее отсекает `.dockerignore`), зависимости Maven сохраняются между сборками. Добавление новых модулей больше не ломает сборку образов уже существующих служб.
- В `discovery` и `config-server` отключён кэш балансировщика нагрузки: эти службы никого не вызывают, и предупреждение при запуске больше не выводится.

## 0.1.0 — 2026-10-02

Каркас проекта и регистр служб. Версия собиралась как `0.1.0-SNAPSHOT`, отдельным выпуском не отмечалась.

### Добавлено
- Родительский `pom.xml` (Java 21, Spring Boot 4.1.1, Spring Cloud 2025.1.2) и общий модуль `common`: события очереди `FileUploadedEvent`, `ProcessingCompletedEvent` и единый формат ошибки `ApiError`.
- `docker-compose.yaml` с PostgreSQL 18 и RabbitMQ 4, сценарий создания схем базы данных по службам (`infra/postgres/init.sql`), `.env.example`.
- Служба `discovery` (регистр служб на Eureka, порт 8761) с проверкой готовности в `docker-compose.yaml`.
- Правила нумерации версий; версия образа службы совпадает с версией проекта (`MEDIAGRID_VERSION`).
