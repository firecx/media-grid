# Служба медиаданных (media-service)

Каталог файлов: метаданные, категории, теги, поиск, статус обработки. Порт 8200, наружу не публикуется: все запросы идут через шлюз по пути `/api/media/**`. Данные хранятся в схеме `media`; схема меняется только через Flyway (`src/main/resources/db/migration`).

Каждый запрос требует токена доступа службы авторизации. Служба проверяет его сама, по открытым ключам с `/api/auth/jwks`. Если ключи ещё не получены, а служба авторизации недоступна, ответ — 503 `SERVICE_UNAVAILABLE`.

## Как файл попадает в каталог

1. Клиент создаёт запись: `POST /api/media`. Ответ — запись со статусом `PENDING_UPLOAD`, её `id` — номер файла.
2. Клиент загружает файл в службу хранения под этим номером (`PUT /api/files/{id}`, см. `storage-service/README.md`). Сохранив файл, она публикует событие `file.uploaded`.
3. Служба медиаданных переводит запись в `UPLOADED`: исходный файл доступен.
4. Служба обработки делает превью и, если нужно, версию для воспроизведения, затем публикует `processing.completed` (см. `processing-service/README.md`). Запись переходит в `READY` или `FAILED`, `hasPreview` показывает, есть ли превью. При `FAILED` исходный файл остаётся доступным, причина — в `processingError`. Ход обработки — `GET /api/processing/{id}`.

Запись, для которой файл не загружен за 24 часа (`mediagrid.media.pending-upload-ttl`), удаляется автоматически, чтобы в каталоге не было записей о несуществующих файлах (ТЗ, п. 4.1.9).

## Права

- Владелец видит свои файлы в любом статусе, меняет и удаляет их.
- `visibility: PUBLIC` — файл видят все вошедшие пользователи (после загрузки), но менять не могут. `PRIVATE` (по умолчанию) — только владелец.
- Администратор видит, меняет и удаляет всё; ведёт справочник категорий.
- Недоступный файл выглядит как несуществующий (404), чтобы не раскрывать его наличие. Попытка изменить видимый чужой файл — 403.

## Программный интерфейс

Ошибки — в едином формате `{"code", "message", "traceId", "timestamp"}`.

### Файлы

| Запрос | Описание |
| --- | --- |
| `POST /api/media` | создание записи перед загрузкой; 201 |
| `GET /api/media` | поиск, ответ `{items, page, size, total}` |
| `GET /api/media/{id}` | одна запись |
| `PATCH /api/media/{id}` | изменение (владелец или администратор) |
| `DELETE /api/media/{id}` | удаление записи; файл удаляет служба хранения по событию `media.deleted`; 204 |
| `GET /api/media/categories` | справочник категорий |

Тело `POST /api/media`:

```json
{
  "title": "Горы",
  "originalFilename": "mountains.mp4",
  "contentType": "video/mp4",
  "sizeBytes": 1048576,
  "categoryId": null,
  "tags": ["горы", "лето"],
  "visibility": "PRIVATE"
}
```

Принимаются только `image/*`, `video/*`, `audio/*` размером до 20 ГБ (`mediagrid.media.max-file-size`). Вид файла (`mediaKind`: `IMAGE`, `VIDEO`, `AUDIO`) определяется по типу.

Тело `PATCH /api/media/{id}` — любые из полей `title`, `categoryId`, `removeCategory: true`, `tags` (заменяют весь список), `visibility`.

Параметры поиска `GET /api/media` (все необязательны, складываются через «и»):

| Параметр | Значение |
| --- | --- |
| `q` | вхождение в название или имя исходного файла, без учёта регистра |
| `type` | `IMAGE`, `VIDEO`, `AUDIO` |
| `status` | `PENDING_UPLOAD`, `UPLOADED`, `READY`, `FAILED` |
| `categoryId` | категория |
| `tag` | тег; можно повторять — файл должен иметь все указанные |
| `mine=true` | только свои |
| `ownerId` | только файлы этого пользователя (из видимых) |
| `sort` | `createdAt` (по умолчанию), `title`, `size` |
| `direction` | `desc` (по умолчанию), `asc` |
| `page`, `size` | страница с нуля и её размер (по умолчанию 20, не больше 100) |

Теги приводятся к нижнему регистру; до 20 тегов на файл, до 50 символов, буквы, цифры, пробел, `_ . -`.

### Категории (только ADMIN)

| Запрос | Описание |
| --- | --- |
| `POST /api/media/admin/categories` `{name, description?}` | создание; 201 |
| `PUT /api/media/admin/categories/{id}` `{name, description?}` | изменение |
| `DELETE /api/media/admin/categories/{id}` | удаление; файлы остаются без категории; 204 |

### Коды ошибок

| Код | Статус | Когда |
| --- | --- | --- |
| `UNSUPPORTED_MEDIA_TYPE` | 400 | не изображение, видео или аудио |
| `FILE_TOO_LARGE` | 400 | размер больше допустимого |
| `INVALID_TAG`, `TOO_MANY_TAGS` | 400 | недопустимый тег или их слишком много |
| `VALIDATION_ERROR` | 400 | некорректные поля запроса |
| `UNAUTHORIZED` | 401 | нет действующего токена |
| `FORBIDDEN` | 403 | недостаточно прав |
| `NOT_FOUND` | 404 | файл или категория не найдены (или недоступны) |
| `CATEGORY_EXISTS` | 409 | категория с таким названием уже есть |
| `SERVICE_UNAVAILABLE` | 503 | нельзя проверить токен: служба авторизации недоступна |

## События

| Событие | Направление | Что делает служба |
| --- | --- | --- |
| `file.uploaded` | получает (очередь `media-service.file.uploaded`) | `PENDING_UPLOAD` → `UPLOADED`; если записи уже нет — публикует `media.deleted` |
| `processing.completed` | получает (очередь `media-service.processing.completed`) | `UPLOADED` → `READY` или `FAILED`. События идут по разным очередям, поэтому итог может прийти раньше `file.uploaded`: тогда запись сразу становится `READY` или `FAILED` |
| `media.deleted` | публикует после фиксации удаления | служба хранения удаляет файл и производные, служба обработки снимает задачу |

Сообщение, которое не удалось обработать, повторяется 3 раза, затем попадает в очередь `<очередь>.dlq`.
